## 1. Описание решения задачи

У нас есть информационная система, в которой разные сервисы записывают логи:
- `auth_service` - логи сервиса авторизации;
- `data_process_service` - логи обработки данных;
- `system_event_handler_service` - логи обработки системных событий.
---
Если логов становится слишком много, они занимают дисковое пространство. Поэтому мы реализовали систему, которая:
1) Хранит логи на отдельном файловом разделе `/LOGS`.
2) Проверяет заполнение файловой системы.
3) Сравнивает заполнение с заданным порогом, по умолчанию 90%.
4) Определяет допустимый размер папки сервиса.
5)  Архивирует старые файлы `.log` в папках, превышающих лимит.
6)  Удаляет исходные логи только после успешного создания архива.
7)  Автоматически тестирует правильность работы на положительных и отрицательных сценариях.

## 2. Как устроен наш проект
### **`logs-lab/`**
* **`mount_logs.sh`** - отвечает за подключение раздела `/LOGS`.

* **`archive_logs.sh`** - реализует основную логику проверки заполнения и архивации логов.

* **`test_archive.sh`** - автоматически проверяет работу архиватора на нескольких положительных и отрицательных сценариях.

* **`setup.sh`** - используется для первоначальной подготовки проекта.

**Кроме файлов проекта используются два системных компонента:**
- **`/etc/fstab`** - хранит настройки автоматического монтирования файловых систем;
- **`mount-logs.service`** - systemd-служба, которая запускает скрипт монтирования при загрузке системы.

## 5. Каталоги логов

В `/LOGS` используются три каталога служб:
```text
/LOGS/
├── auth_service/
├── data_process_service/
└── system_event_handler_service/
```
Скрипт архивирования обрабатывает файлы с расширением `.log`, расположенные непосредственно в каталогах этих служб.

---
## 6. Основные параметры архивирования

| Параметр | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| **LOGS_DIR** | `/LOGS` | Каталог с логами |
| **THRESHOLD** | `90` | Порог заполнения дискового пространства в процентах |
| **BATCH_SIZE** | `10` | Максимальное количество лог-файлов в одной партии |
| **TEST_TOTAL_KB** | - | Тестовая виртуальная ёмкость для автоматических проверок |

**Лимит на один каталог рассчитывается по формуле:**

```text
Лимит = (Общая ёмкость * Порог / 100) / 3
```

## 7. Автоматическое тестирование
В проект входит скрипт `test_archive.sh`, который автоматически проверяет работу архиватора.

### **Проверяются следующие сценарии:**
---
#### **Положительные**
- **Тест 1. Архивирование папок сверх лимита**

**Что создали:** две папки по `1000 КБ` и одну папку размером `800 КБ`.
Общая тестовая ёмкость — `3000 КБ`, порог — `90%`.
Лимит одной папки составляет `900 КБ`.
Поэтому первые две папки должны архивироваться, а третья — нет.

**Что проверяли:** появились ли архивы в `auth_service` и `data_process_service`.

**Результат:** `PASS`.

---
- **Тест 2. Удаление оригиналов после успешной архивации**

**Что проверяли:** после создания архивов исходные .log-файлы должны исчезнуть из двух папок, которые превышали лимит.
Это важно, потому что цель архивации — не только сохранить логи в архиве, но и освободить место.

**Результат:** `PASS`.

---
- **Тест 3. Папка в пределах лимита не архивируется**

**Что проверяли:** Папка system_event_handler_service имеет размер 800 КБ при лимите 900 КБ.
Скрипт должен пропустить эту папку, не создавать архив и оставить оба исходных файла. Тест проверяет количество архивов и оставшихся логов. Если архивов нет и логи сохранились, тест проходит».

**Результат:** `PASS`.

---

#### **Отрицательные**
- **Тест 4. Заполнение диска ниже порога**

**Что создали:** шесть файлов по 300 КБ — по два в каждой из трёх папок.
Общий объём — 1800 КБ из 3000 КБ:
Поскольку 60% меньше порога 90%, архивирование не должно запускаться.

**Что проверяли:** архивов нет, все шесть исходных логов сохранены.

**Результат:** `PASS`.

---
- **Тест 5. Некорректное значение порога**

**Что сделали:** передали программе `THRESHOLD=101`.
Допустимый диапазон — от 1 до 100. Значение 101 некорректно.

**Что проверяли:** программа должна завершиться с ошибкой, а не продолжить архивирование с неправильными настройками.

**Результат:** `PASS`.

---
- **Тест 6. Ошибка создания архива**

**Что сделали:** подменили команду `tar` тестовой командой, которая всегда завершается с ошибкой.
Благодаря этому нам не нужно специально ломать настоящую файловую систему: мы искусственно имитируем неудачное архивирование.

**Что проверяли:** 
- скрипт завершился с ошибкой;
- оба исходных .log-файла остались;
- неполный архив отсутствует.

**Результат:** `PASS`.
