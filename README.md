## 1. Описание решения задачи

У нас есть информационная система, в которой разные сервисы записывают логи:
- `auth_service` - логи сервиса авторизации;
- `data_process_service` - логи обработки данных;
- `system_event_handler_service` - логи обработки системных событий.
---
Если логов становится слишком много, они занимают дисковое пространство. Поэтому мы реализовали систему, которая:
1) Хранит логи на отдельном файловом разделе `/LOGS`.
2) Проверяет заполнение файловой системы.
3) Сравнивает заполнение с заданным порогом, по умолчанию 90%.
4) Определяет допустимый размер папки сервиса.
5)  Архивирует старые файлы `.log` в папках, превышающих лимит.
6)  Удаляет исходные логи только после успешного создания архива.
7)  Автоматически тестирует правильность работы на положительных и отрицательных сценариях.

## 2. Как устроен наш проект
```text
### **`logs-lab/`**
*   ### `archive_logs.sh`
    Основной алгоритм проверки заполнения диска и архивации логов. Скрипт опрашивает занятость раздела `/LOGS` и при превышении лимита точечно архивирует старые данные переполненных сервисов.

*   ### `mount_logs.sh`
    Скрипт инициализации дисковой подсистемы. Проверяет, смонтирован ли раздел `/LOGS`, и при необходимости автоматически подключает его к системе.

*   ### `setup.sh`
    Файл первоначальной настройки проекта, который выполняет конфигурацию окружения, создание необходимых системных служб автозапуска и первичную разметку.

*   ### `test_archive.sh`
    Скрипт автоматического тестирования функционала. Самостоятельно создаёт изолированные тестовые данные, заполняет ими директории, запускает основной алгоритм очистки и сравнивает полученный результат с ожидаемым.

*   ### `restore_test/`
    Служебный каталог, куда в процессе тестирования распаковывался архив для проверки корректности восстановления исходных логов ИС.
```
